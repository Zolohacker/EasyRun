# 开箱即用与数据保全

## 第一次启动

1. 启动 PostgreSQL 与平台。Windows 的 `scripts/start-local.ps1` 会按需初始化本地数据库；Docker 运行 `docker compose up -d --build`。
2. 主密钥自动生成在 `data/account-master.key`，使用系统随机源生成 32 字节。Windows 设置受限 ACL，Linux 使用 `0600` 权限；重启复用原文件。
3. 打开网页，设置超级管理员邮箱和密码、选择使用模式。
4. 管理总览提示补充地图配置：进入「系统配置 → 地图与执行器」添加高德 Web 服务 API Key，每个 Key 默认 3 QPS。Key 加密保存在数据库，环境变量中的地图 Key 不再读取。
5. 人脸模型和 Windows/Linux 对应运行库随仓库及完整发行包提供，自动匹配路径，系统配置显示真实加载状态。

项目代码的使用模式与第三方模型用途条款相互独立，随附模型的限制见 [models/NOTICE.md](../models/NOTICE.md)。

## 必须备份的材料

- PostgreSQL 数据库。
- **`data/account-master.key`**：用于解密钱包种子、账号凭据、地图密钥等。
- 钱包助记词 / 旧版 seed 的离线备份。

三者应分别备份。生成新密钥并不能恢复旧密钥加密的数据，程序不会用新密钥静默覆盖已有加密部署。

Docker 的 `easyrun_data` 卷存放主密钥，`easyrun_db` 卷存放数据库，`easyrun_runtime` 卷存放在线更新的程序及回滚文件；升级、重建容器时保留三个卷。`docker compose down -v` 会删除卷，请勿将其当作普通升级步骤。自定义 `EASYRUN_DATA_DIR` 时应使用持久可写目录，不要放在每次重建会清空的临时目录。程序卷必须独立于数据卷，每个运行实例使用独立程序卷。

## 旧部署升级

- 原 `ACCOUNT_MASTER_KEY` 仅作为旧部署迁移入口：首次升级会把**原值**保存到主密钥文件，不重新生成、不重新加密钱包。
- 若持久文件与旧环境密钥不一致，启动会明确报错，先核对原部署备份。
- 若文件缺失且数据库已有加密数据，启动会要求恢复原文件或提供原密钥，不会创建一把新钥匙掩盖问题。
- 已存数据库的地图 Key 保留不变；原 `MAP_API_KEY` 环境变量不再参与初始化。
- 原平台更新凭据已停用；历史数据库中的旧凭据会清空。更新始终访问公开仓库，无凭据设置项。

## 部署参数

新部署只需确保 PostgreSQL 可连接。Docker 的数据库密码在 `.env` 配置；应用主密钥、地图 Key、人脸模型路径均不再要求手填。HTTPS 反向代理继续按实际情况配置 `COOKIE_SECURE=true`。
